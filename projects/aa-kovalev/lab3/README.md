# Лаба 3. Диалоговые агенты для квизов по Python

Три варианта агента работают с учебником «Укус Питона» и общим хранилищем
квизов: `custom` (PydanticAI), `smolagents` (ToolCallingAgent) и
`coding` (smolagents.CodeAgent с исполнением Python). Все используют
`qwen2.5:7b` через Ollama и общие инструменты. В [REPORT.md](REPORT.md)
сравниваются исходная и новая конфигурации `custom`, а также сохранён исходный
эксперимент с `smolagents.ToolCallingAgent`. Полных оценок `coding` пока нет.

## Запуск

Сначала подготовьте активный индекс и запустите Qdrant по [инструкции Лабы 2](../lab2/README.md).
Команды ниже выполняются из каталога `projects/aa-kovalev/lab3` в PowerShell.

```powershell
uv sync --locked
if (!(Test-Path .env)) { Copy-Item .env.example .env }
ollama pull qwen2.5:7b
docker compose up -d
uv run --locked uvicorn app:app --app-dir source --host 127.0.0.1 --port 8000
```

Ollama должна быть запущена. Для сравнения задайте одинаковое контекстное окно Ollama для всех агентов.
В исходном эксперименте для Ollama предполагалось окно 32 768 токенов.
Текущий бюджет `custom` в `config.json` — **17 288 токенов** с резервами
(порог сокращения истории — **13 960**). Фактическую настройку `num_ctx`
Ollama необходимо проверить отдельно. Langfuse открывается на [порту 3000](http://localhost:3000).
Локальный проект и ключи создаются через Compose. Настройки подключения и
данные входа берутся из `.env`.

[Веб-чат](http://127.0.0.1:8000) использует `custom`. Из чата можно открыть
созданный квиз и проверить ответы. Квизы хранятся в `quizzes.sqlite3`,
история чата — в `dialogues.sqlite3`. У экспериментальных задач отдельные
сессии, поэтому их квизы не смешиваются с веб-коллекцией.

## Инструменты и промпты

| Инструмент | Назначение |
|---|---|
| `search_book` | Поиск в RAG из Лабы 2 |
| `list_quizes` | Список квизов с названием, ссылкой и ID |
| `get_quiz_info` | Чтение квиза или одного вопроса без ключей |
| `manage_quiz` | Создание и удаление квиза, добавление, правка и удаление вопросов |

Инструкции агента находятся в `prompts/system.txt`. Схемы инструментов
генерируются из кода в `source/tools/definitions.py`: описания параметров
находятся в Google-style docstrings общих функций (`search_book`,
`manage_quiz`, `list_quizes`, `get_quiz_info`), а Pydantic-класс
`Question` и `QuizAction` (Literal) используются как аннотации типов.
PydanticAI строит схемы и валидацию через `Tool`, smolagents — через
нативный `tool()`. Файл `prompts/tools.json` больше не нужен.

**Адаптация вложенных моделей** — smolagents 1.22.0 `@tool` декоратор транслирует
`BaseModel` в пустой `{"type": "object"}`, теряя ограничения полей.
Мост в `smolagents_tools.py` подставляет `Question.model_json_schema()`
в параметры `question` и `questions`, сохраняя `minLength`, `maxLength`,
`minItems`, `maxItems` и другие ограничения. Входные словари преобразуются
в `Question` через Pydantic `validate_call`, включая проверку валидаторов модели.

Для загрузки системного промпта из Langfuse
создайте текстовый промпт `lab3-system` с меткой `production`, задайте
`LANGFUSE_PROMPT_NAME=lab3-system` и перезапустите процесс. Версия промпта
попадёт в метаданные трейса.

## Эксперимент

Все три сохранённых полных прогона выполнены 6 ноября 2026 года на
одних 18 заданиях и 39 репликах на агента, с `rubric_version=2`:
`20261106T091347Z-f13a68` (исходный `custom`),
`20261106T092905Z-775cec` (`smolagents.ToolCallingAgent`) и
`20261106T115324Z-41891f` (новый `custom` с многоуровневым
сокращением истории). Последний **не является прогоном CodeAgent**.
В сравнении двух версий `custom` совпадают входные запросы, эталоны
и разметка, но одновременно с механизмом контекста менялись также
бюджет и отдельные части приложения; чистой абляцией это не является.
Подробности и ссылки на ошибки — в [REPORT.md](REPORT.md).

В разметке `expected_tools` перечислены обязательные инструменты, а
`expected_actions` — обязательные действия `manage_quiz`. Для L01–L03
создание квиза без просьбы обратиться к книге больше не требует `search_book`.
В S07–S09 чтение созданного квиза остаётся обязательным: оно явно запрошено.
Проверка действия отличает удаление квиза от удаления вопроса; правильный ID,
номер вопроса и содержимое по-прежнему проверяются по снимкам и критерию судьи.

Все три агента получают одинаково ограниченную выдачу поиска: суммарно до 4000 символов текста,
с ID, PDF-страницами и признаком сокращения фрагмента. Полные найденные чанки
остаются во вложенном retrieval-span и данных для retrieval-метрик.
Содержимое квиза больше не обрезается посреди JSON. Общая валидация создания
выполняется хранилищем; одинаковые ошибки доступны обоим агентам.

`custom` использует адаптер бюджета поверх стратегий PydanticAI Harness.
`ClearToolResults` очищает старую выдачу, `SummarizingCompaction` сжимает
завершённые ходы, `SlidingWindowCompaction` остаётся запасным вариантом.
Порог и проверка используют один подсчёт: токенизатор Qwen для сериализованных
сообщений, инструкций и реальных схем инструментов. Это консервативная оценка,
а не точный размер HTTP-запроса Ollama.

Текущий ход (запрос, вызовы и результаты инструментов) исключён из сокращения.
Перед каждым запросом проверяется бюджет с резервом роста; если после штатных
стратегий места всё ещё мало, удаляются старейшие завершённые ходы.
`keep_tokens` у библиотеки — минимум сохраняемого хвоста, поэтому он не
используется как гарантия максимального размера. Если даже текущий ход без
старой истории больше входного бюджета, возвращается явная ошибка.

Фокус сводки задан в `prompts/summary_focus.txt`: цель, ограничения, точные ID,
важные факты и подтверждённые действия. Сохранность фактов зависит от качества
модели; утраченные ID нужно восстанавливать через список квизов, а не угадывать.
Суммаризация учитывается в расходе запросов, времени и токенов.
`context-trim` показывает этапы и размер до/после, `context-check` — размер
на каждом шаге. Никакого отдельного закрепления ID по тексту запроса нет.

История после ошибок сохраняется через `capture_run_messages` и
`repair_messages`. Агенты `smolagents` и `coding` используют штатную
память без автоматической обрезки. `CodeAgent` исполняет сгенерированный
код локально: это не полноценная изоляция от недоверенного кода.

Для `coding` используется родной механизм `CodeAgent` со входными
Python-блоками в формате Markdown (`code_block_tags="markdown"`).
Поскольку `smolagents` в Python-подсказке показывает лишь тип `array`
для `questions`, в инструкции `CodeAgent` добавлен пример структуры
вопроса (`text`, `options`, `correct`), вызова `manage_quiz` и проверки
результата. Для диагностики в Langfuse ищите `coding-turn`, вложенные
`CodeAgent.run`, `Step`, генерацию модели и вызовы инструментов;
исполнение кода фиксируется как шаг агента. Объём генерации для всех
агентов по-прежнему ограничен `max_output_tokens=1024`; длинный код
создания квизов может обрезаться, и это следует проверять отдельно.

Сверка API: [история PydanticAI](https://ai.pydantic.dev/message-history/),
[ограничения PydanticAI](https://ai.pydantic.dev/agent/),
[ToolCallingAgent и CodeAgent](https://huggingface.co/docs/smolagents/en/reference/agents),
[Compaction в PydanticAI Harness](https://ai.pydantic.dev/harness/compaction/).

`tasks.json` содержит 18 задач и 39 реплик на агента. Веб-сервер для
прогона не требуется. Пробный запуск проверяет загрузку датасета, ответы,
вызовы инструментов и доступность связанных трейсов.

После изменения разметки нужны новые прогоны и новые оценки судьи.
Старые `runs.jsonl` содержат прежнюю разметку: `evaluate.py` намеренно не
подменяет её текущим `tasks.json`. Загрузка создаёт новые версии элементов
по содержимому; прежние элементы и результаты в Langfuse не удаляются.

```powershell
uv run --locked python source/load_dataset.py
uv run --locked python source/run.py --publish-dataset --agent custom --tasks S01 S07 D01
```

Для запуска отдельных вариантов и публикации в Langfuse:

```powershell
uv run --locked python source/run.py --publish-dataset --agent custom
uv run --locked python source/run.py --publish-dataset --agent smolagents
uv run --locked python source/run.py --publish-dataset --agent coding
```

`--agent both` запускает старую пару `custom` + `smolagents`, а
`--agent all` — все три варианта. Для демонстрации третьего агента
достаточно `--agent coding --tasks S01 D01 L01`.

Каждый запуск печатает папку `results\…`. В ней находятся ответы, вызовы,
снимки квизов, метаданные и эталонные чанки. Полный прогон включает
39 реплик на каждого выбранного агента. В **Datasets → lab3-agent-turns** видны только
прогоны, опубликованные через `--publish-dataset` или привязанные
к датасету отдельно: импорт оценок в трейсы сам по себе не создаёт
строки dataset run.

### Оценки и метрики

Для сводного отчёта использованы внешние бинарные оценки
`external_judge`, импортированные в трейсы соответствующих прогонов,
и сгенерированные `evaluate.py` файлы `summary.csv` и `report.md`.
В сводном [REPORT.md](REPORT.md) отдельно сравниваются **успешность реплик**
(исходный `custom`: 11/39 = 28,2%; новый `custom`: 18/39 = 46,2%),
**успешность контекстных реплик** (20% → 40%) и **успешность целых заданий**
(4/18 = 22,2% в обоих прогонах `custom`; 0/18 в исходном
`smolagents.ToolCallingAgent`). Технический статус `success` не означает,
что выполнены все условия задания.

Пересчёт именно сохранённых прогонов:

```powershell
uv run --locked python source/evaluate.py ".\results\20261106T091347Z-f13a68" --judge-score external_judge
uv run --locked python source/evaluate.py ".\results\20261106T115324Z-41891f" --judge-score external_judge
uv run --locked python source/evaluate.py ".\results\20261106T092905Z-775cec" --judge-score external_judge
```

Для воспроизведения внешней оценки `source/export_judge.py` принимает
один или несколько файлов `runs.jsonl`, включая `coding`. Каждая выходная строка содержит `trace_id` и пакет
данных для судьи. Для контекстных реплик передаётся история обеих сторон,
для изменения квизов — доступные снимки состояния. Вердикт `1` требует
выполнения всех обязательных условий, иначе ставится `0` с пояснением.
Файл оценок записывается через `source/import_judge.py`. Экспортёр и импортёр
находятся в `lab3/source`.

```powershell
uv run --locked python source/export_judge.py ".\results\ПРОГОН_CUSTOM\runs.jsonl" ".\results\ПРОГОН_SMOLAGENTS\runs.jsonl" -o judge_cases.jsonl
uv run --locked python source/import_judge.py .\langfuse_external_scores.jsonl
```

Вторая команда выполняется после получения оценок. Импортёр ожидает JSONL
с полями `id`, `traceId`, `name`, `value`, `dataType` и `comment`.
Для `external_judge` идентификатор создаётся как
`uuid5(NAMESPACE_URL, traceId + '/external_judge')`.

Для встроенного судьи настройте в Langfuse LLM Connection и оценщик
`QWEN-Evaluator`. Выберите **Dataset runs → New dataset run items**, фильтр
`lab3-agent-turns` и 100%. Передайте в промпт вход элемента, выход трейса
и ожидаемый результат. Оценщик должен вернуть `1`, если все проверяемые по
ответу условия выполнены, иначе `0`. После появления оценок вызовите
`evaluate.py` с папкой прогона. По умолчанию скрипт читает `QWEN-Evaluator`.

`evaluate.py` создаёт `summary.csv` и `report.md`, публикует оценки реплик
и задач и записывает агрегаты в трейсы `run-summary`. Сравнение по задачам
считается отдельно от среднего балла по репликам.

### Результаты для защиты: новая схема контекста

У нового `custom` успешность **отдельных реплик повысилась почти до 50%**;
это не означает повышения успешности целых заданий. Важный результат —
улучшение работы с контекстными репликами, но увеличение задержки.

| Метрика | Исходный `custom` | Новый `custom` | `smolagents` (исходный) |
|---|---:|---:|---:|
| Успех отдельных реплик | 11/39 (28,2%) | **18/39 (46,2%)** | — |
| Успех целых задач | 4/18 (22,2%) | **4/18 (22,2%)** | 0/18 (0%) |
| Успех контекстных реплик | 3/15 (20%) | **6/15 (40%)** | 0% |
| Успех контекстных реплик после сокращения | 0/6 | **3/6 (50%)** | — |
| Успех диалогов целиком | 1/9 | **0/9** | 0/9 |
| Среднее время задачи | 49,61 с | **82,73 с** | 72,85 с |
| Средние входные токены/задачу | 13 454,94 | 17 306,33 | 19 548,76* |

**Разница успеха реплик**: +18 процентных пунктов, или +63,6% относительно
старого результата. **Разница времени**: +33,12 с на задачу (+66,8%).
Новый прогон: 14 проваленных заданий — 8 содержательных отклонений судьи,
5 случаев отсутствия обязательного успешного инструмента и 1 таймаут.
Часто встречаются неверные ответы в квизах (`pop`/`remove`, `del`/`pop`),
четыре варианта вместо требуемых трёх, нерелевантная тема вопроса и
пропущенные `list_quizes`/`get_quiz_info`. На средних и сложных
заданиях целиком не выполнено ни одного сценария.

**Ограничение вывода:** различались и другие параметры (в том числе
бюджет контекста 12 288 → 17 288 токенов), поэтому нельзя приписывать
весь прирост только `TieredCompaction`. Также отсутствуют новые полные
оценки RAG-метрик и измерения для CodeAgent. Подробные трейсы, разбор
и архив сравнения двух исходных агентов приведены в [REPORT.md](REPORT.md).

* Для исходного `smolagents` метрики токенов доступны не для всех задач.

## Демонстрация на защите

1. В чате попросите создать квиз по учебнику. Откройте его, затем попросите
   изменить конкретный вопрос в том же квизе.
2. В Langfuse откройте обе реплики по общему `session_id`. Покажите корневой
   трейс реплики, запрос к модели, вызовы инструментов, результаты и вложенный
   `retrieval` с найденными чанками и оценками поиска.
3. Для демонстрации сокращения запустите
   `uv run --locked python source/run.py --agent custom --tasks L01`.
   Найдите span `context-trim` и сравните историю до и после. Если с обычным
   окном событие не появилось, уменьшите `context_tokens` для отдельного
   демонстрационного прогона и укажите это при показе. Сокращение может сработать и внутри цикла инструментов, до очередного запроса к модели.
4. Откройте сравнение исходного и нового `custom` и `run-summary`. Покажите один случай
   пропущенного инструмента и один случай неверной правки квиза из отчёта.

Для L01–L03 разметка требует фактического сокращения перед хотя бы одной
контекстной репликой. Если его не было, `evaluate.py` добавляет предупреждение
в отчёт. Число реплик не заменяет проверки превышения токенного бюджета.

## Локальные проверки

Без сервисов и обращения к модели, из каталога лабы:

```powershell
$env:PYTHONPATH = 'source'
uv run --locked python -m unittest discover -s tests -v
```

Проверяются сохранение истории и расхода после сбоя, единая выдача
инструментов и различение действий при оценке. Новые тесты не добавлялись.
Дополнительно тестируются имена и описания инструментов, enum действий,
nullable/дефолтные аргументы, ограничения вложенной схемы `Question`,
паритет dispatch и отклонение невалидных `Question` через Pydantic.
