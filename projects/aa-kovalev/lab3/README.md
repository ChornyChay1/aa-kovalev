# Лаба 3: диалоговый агент по «Укусу Питона»

Свой цикл native tool calling сравнивается с готовым `smolagents.ToolCallingAgent`.
Одна модель `qwen2.5:7b`, один индекс Лабы 2, одинаковые три инструмента:
`search_book`, `read_page`, `calculate`. MCP, прокси, планировщика и LLM-судьи нет.
Gemma из Лабы 2 здесь заменена моделью с tool calling; эмбеддинги и поиск прежние.

## Запуск

Команды из `projects/aa-kovalev/lab3`, PowerShell. Нужны Docker Desktop,
Ollama и уже подготовленный индекс Лабы 2 (`../lab2/artifacts/active.json`).
Если индекса нет, выполните инструкцию Лабы 2. Qdrant запускается её Compose.

```powershell
uv sync --locked
Copy-Item .env.example .env
ollama pull qwen2.5:7b
docker compose up -d
```

Compose основан на официальном примере Langfuse v3.114.0; SDK закреплён на v3.15.0.
Он поднимает web, worker, PostgreSQL, ClickHouse, Redis и MinIO.
Это **локальная** конфигурация: порты доступны только с этого компьютера,
пароли в примере не предназначены для публикации сервера.

Откройте http://localhost:3000 и войдите с `LANGFUSE_USER_EMAIL` /
`LANGFUSE_USER_PASSWORD` из `.env`. Проект `lab3` и ключи создаются при первом
старте автоматически. Проверьте наличие проекта; старт миграций может занять время.
В Project Settings → Models добавьте модель `qwen2.5:7b`, шаблон `^qwen2\.5:7b$`,
цены input/output **0 USD/token**: это позволит Langfuse показывать стоимость
LLM-вызовов готового агента. Токены берутся из ответа API, не из токенизатора Langfuse.
Ключи, URL и учётная запись задаются в `.env`; файл не коммитится.

Задайте окно модели **32768** в настройках Ollama; проверьте `ollama ps` после
первого запроса. Если запускаете сервер вручную, закройте уже работающую Ollama
и в отдельном PowerShell выполните:

```powershell
$env:OLLAMA_CONTEXT_LENGTH = "32768"
ollama serve
```

Это общее окно модели для обоих агентов. Свой агент дополнительно ограничен
4096 токенами в `config.json`. Готовый использует собственное поведение памяти;
это различие фиксируется в отчёте, а не выдаётся за сравнение при равном бюджете.
Большое окно может увеличить использование RAM/VRAM.

Проверка подключения и короткий прогон, затем весь датасет:

```powershell
uv run --locked python source/run.py --tasks S01 D01
uv run --locked python source/run.py
```

`run.py` проверяет авторизацию Langfuse до начала. Он сохраняет отдельную папку
`results/<run_id>/`; `--agent custom` или `--agent smolagents` запускает одну систему.
`--index <путь>` позволяет выбрать конкретный каталог индекса вместо active.json.
Для сравнения используйте один вызов без `--agent`: тогда конфигурация и задания
общие, каждый диалог имеет независимую сессию, а все его реплики — одного агента.
Перед измерениями прогрейте модель коротким прогоном; результаты включают HTTP,
retrieval и генерацию. Идентификатор индекса и полная конфигурация сохраняются.

## Оценка

1. Откройте `results/<run_id>/review.csv`. Для **каждой** реплики поставьте
   `success=1` или `0` по `expected_output`, сверяя факты и ссылки с источником.
   Проверяйте и выполнение обязательных частей запроса, включая инструменты.
2. Для нулей заполните `error_category` и `comment` после чтения трейса по
   `trace_url`: наблюдаемое поведение, место сбоя, объяснение по данным трейса.
   Категории выделите по реальным ошибкам; не подгоняйте оценки под ожидаемый итог.
3. Выполните:

```powershell
uv run --locked python source/evaluate.py results/<run_id>
```

Скрипт создаёт `summary.csv`, `report.md`, отправляет оценки реплик и сессий,
а также отдельные агрегированные трейсы `run-summary` в Langfuse. Метрики
привязаны к тегам агента, версии, модели и прогона. Повторная загрузка индивидуальных
оценок использует стабильные ID. Пустые ручные оценки не считаются неудачами:
оценивание останавливается до заполнения CSV.

Task success для диалога — успех **всех** его реплик. Контекст — доля успешных
ответов только на помеченные history-dependent реплики, отдельно до первого
сокращения и после него. Дополнительно считаются шаги, инструменты, максимальный
входной контекст, токены, стоимость и время; доля задач с техническими ошибками
включает восстановленные ошибки инструментов. Превышение шагов выводится отдельно.

Recall@k, Precision@k, MRR используют те же эталонные PDF-страницы → ID чанков,
что Лаба 2; k задан в конфигурации. При нескольких поисках на реплику берётся
среднее метрик отдельных поисков; без поиска метрики равны нулю. Это качество
поисковых запросов агента, а не оценка объединённой выдачи. Tool correctness —
вызваны ли все ожидаемые инструменты, не проверка оптимальности их аргументов.

Нулевые тарифы означают отсутствие платы за локальный API; электричество,
оборудование и retrieval в денежную стоимость не включены. При замене модели
обновите `model`, совместимый `tokenizer`, тарифы и модель в Langfuse.

## Демонстрация

```powershell
uv run --locked python source/run.py --chat --agent custom
```

Пустая строка завершает диалог. После каждой реплики выводится ссылка на трейс.
Для демонстрации сокращения выполните `--tasks L01 --agent custom`, затем откройте
сессию в Langfuse: `user-turn → iteration-N → context-trim / llm / tool → retrieval`.
`context-trim` содержит размеры до/после и удалённые сообщения; полные результаты
поиска остаются в retrieval-span, даже если для модели их текст сокращён.
Логируются сообщения, действия и результаты, а не недоступные внутренние мысли модели.

Остановка без удаления данных: `docker compose down`.

## Состояние сдачи

Код, датасет, конфигурация и основа отчёта подготовлены. Реальный эксперимент,
проверка браузера Langfuse, оценки и разбор неудач **ещё не выполнены**: в среде
разработки нет Docker, Ollama и локального индекса. Числа качества не выдуманы.
После запуска дополните `REPORT.md` таблицей и выводами из `results/<run_id>/report.md`.
Если оказалось меньше пяти неудачных задач на агента, скрипт явно сообщит об этом;
это требование сдачи остаётся незакрытым, а не заменяется вымышленными случаями.
