# Лабораторная работа №1

## Описание задания

Развернуть три большие языковые модели разных семейств через OpenAI-совместимый
REST API. Подготовить три русских промпта для генерации, классификации и извлечения
данных. Сравнить ответы с настройками движка по умолчанию и после изменения
гиперпараметров. Сохранить ответы, измерить токены, время и скорости, оценить
точность, стабильность, повторения и фактические ошибки.

## Использованные технологии и модели

- Движок: **Ollama 0.35.1**, локальный сервер.
- API генерации: `POST http://localhost:11434/v1/chat/completions`, потоковый ответ.
- Язык: **Python 3.11.9**; зависимости управляются через **uv**, версии закреплены в `uv.lock`.
- Библиотеки: **httpx** для REST-запросов, **psutil** для поиска процесса токенизатора;
  **pandas** и **matplotlib** для анализа, **ipykernel** для запуска ноутбука.
- Оборудование: **NVIDIA GeForce RTX 3060 Laptop GPU, 6144 МиБ**, драйвер 581.80.
- Система: Windows 10, сборка 19045.

| Модель в Ollama | Семейство | Число параметров по метаданным | Квантование |
| --- | --- | --- | --- |
| `qwen2.5:3b` | Qwen | 3,1 млрд | Q4_K_M |
| `llama3.2:3b` | Llama | 3,2 млрд | Q4_K_M |
| `gemma3:4b` | Gemma | 4,3 млрд | Q4_K_M |

Три семейства различаются архитектурой, размером и токенизаторами. Gemma использована
только для текстовых запросов. В диагностике `/api/ps` у всех моделей зафиксирован
контекст **4096 токенов**. Запросы выполнялись последовательно, сначала все задания
одной модели, затем следующей. Версии, идентификаторы моделей, параметры и размещение
сохранены в файлах эксперимента.

### Точность и соблюдение инструкций

Для P2/P3 правильность значений по смыслу отделена от выполнения формата. При
смысловой оценке снимается внешняя Markdown-обёртка; для P2 допускается нумерованный
список и удаляются пробелы по краям меток. Для P3 допускаются `ё/е`, название с
типом товара и эквивалентные обозначения чёрного цвета, включая `black`.
Строгий результат требует заданный JSON-объект без Markdown; метки P2 должны
точно совпадать с допустимыми. Неправильные факты при разборе не исправляются.

| Qwen | 100% / 100% | 2/5 / 1/5 | 5/5 / 5/5 | 5/5 / 5/5 |

### Примеры и фактические ошибки

**P1, Qwen, B, повтор 1:** факты сохранены, но письмо содержит только 28 слов.

```text
Уважаемая Мария,

Прошу вас подтвердить перенесение встречи по проекту "Атлас" с 12 октября, 14:00, на 13 октября, 11:00, из-за того что отчёт ещё не готов.

С уважением,
Артём
```

**P2, Llama, B, повтор 1:** классификация и формат правильны.

```json
{"1": "Billing", "2": "Tech support", "3": "Sales", "4": "Billing", "5": "Tech support", "6": "Sales"}
```

**P3, Llama, A, повтор 2:** модель вернула `"warranty_months": 12`, хотя гарантия
в описании отсутствует. Это явная галлюцинация; ожидается `null`. В B подобных
ошибок гарантии нет. Другие ошибки и неподтверждённые утверждения:

- Qwen, P1/A/3: причина переноса заменена на «на основании вашего отчета»,
  авторство отчёта приписано Марии.
- Llama, P1/A/3: добавлены неоднозначность отчёта и занятость автора.
- Llama, P1/B/5: добавлено обращение «Правительству».
- Gemma, P1/A/4: утверждается, что потребуется больше времени для обсуждения.

Нарушение Markdown-формата и ошибка классификации учитываются отдельно от
выдуманного факта. Не каждое правдоподобное уточнение объявляется галлюцинацией.

### Стабильность и повторяемость

Число разных полных текстов из пяти ответов:

| Модель | P1 A / B | P2 A / B | P3 A / B |
| --- | --- | --- | --- |
| Qwen | 5 / 3 | 2 / 2 | 2 / 2 |
| Llama | 5 / 5 | 5 / 1 | 4 / 4 |
| Gemma | 5 / 5 | 2 / 1 | 4 / 2 |

После нормализации по правилам смысловой оценки P2/P3 результаты Qwen и Gemma
одинаковы во всех повторах каждого режима. У Llama P2 число разных результатов
снижается с 3 до 1, у P3 — с 2 до 1. Для P1 нормализуются только пробелы.
Устойчивый ответ может нарушать инструкцию: стабильная Markdown-обёртка Gemma
не делает формат правильным.

Повторные тройки слов внутри ответа почти отсутствуют: ненулевое значение есть
только у одного письма Gemma в A. Средняя доля повторных троек в этой группе —
около **0,004**. Совпадение пяти ответов не доказывает детерминизм; `seed` не фиксирован.

## Выводы

1. Три квантованные модели разных семейств успешно работали на RTX 3060 Laptop
   через OpenAI-совместимый REST API. Все 90 ответов и необходимые измерения сохранены.
2. Тюнинг не улучшает все задачи одновременно. У Llama выросла точность
   классификации с 90% до 100% и исчезла выдуманная гарантия, но ухудшилось соблюдение
   формата P3. Иностранные вставки в письмах сохранились.
3. Qwen наиболее надёжно выполняла извлечение: все ответы P3 правильны по смыслу
   и формату. Gemma сохраняла факты и давала связные русские письма, но нарушала
   объём писем и систематически добавляла Markdown в структурированные ответы.
4. Настройки B сократили среднюю длину письма Qwen с 86,6 до 76,6 токена, Llama —
   с 146,0 до 115,4; Gemma увеличила её с 115,2 до 119,4. Время менялось вместе с
   длиной. Серверная скорость генерации между A и B изменилась мало.
5. Лимит `max_tokens=512` ни разу не обрезал ответ, поэтому его влияние в этом
   эксперименте не проявилось. Одновременное изменение настроек не позволяет
   выделить отдельный эффект `temperature` или `top_p`.

Ограничения: пять повторов, три фиксированных промпта, разные дефолты и токенизаторы,
кэшированные входы, последовательная работа моделей и ручная оценка писем одним
проверяющим. Выводы относятся к этому запуску, а не к качеству семейств в целом.
Ошибка генерации не означает ошибку проведения лабораторной: нарушения инструкций
и галлюцинации являются результатом эмпирического анализа.

## Инструкция по запуску

1. Установить [Ollama](https://ollama.com/download/windows) и
   [uv](https://docs.astral.sh/uv/getting-started/installation/). Запустить приложение
   Ollama. Для ручного запуска вместо приложения можно использовать отдельный
   PowerShell; одновременно нужен один сервер:

   ```powershell
   $env:OLLAMA_CONTEXT_LENGTH = "4096"
   ollama serve
   ```

2. Скачать модели:

   ```powershell
   ollama pull qwen2.5:3b
   ollama pull llama3.2:3b
   ollama pull gemma3:4b
   ```

3. Из корня репозитория перейти в лабораторную и установить зависимости:

   ```powershell
   cd projects/aa-kovalev/lab1
   uv sync --locked --group analysis
   ```

4. Проверить доступ к API:

   ```powershell
   uv run --locked python source/check_connection.py --model qwen2.5:3b
   ```

   Для остальных моделей изменить `--model`. Первый запрос может включать загрузку
   модели. Размещение и контекст можно проверить командой `ollama ps`.

5. Выполнить эксперимент:

   ```powershell
   uv run --locked python source/run_experiment.py
   ```

   Выполняются 90 основных прогонов, три прогрева и замеры токенизации.
   Новые `runs.jsonl`, `metadata.json`, `summary.csv` сохраняются в отдельную папку
   `results/<время>_<идентификатор>/`; она исключена из git. Адрес сервера при
   необходимости задаётся через `--base-url http://localhost:11434/v1`.
   Перед запуском подключить ноутбук к питанию и закрыть приложения, нагружающие GPU.
   Параметры A намеренно не задаются; B определён в `source/run_experiment.py`.

6. Открыть `source/analysis.ipynb` в VS Code с расширением Jupyter, выбрать
   интерпретатор `lab1/.venv` и выполнить все ячейки. Для просмотра и пересчёта
   сохранённого запуска Ollama не требуется. Ноутбук читает
   `data/run_20261004_181757/`; чтобы анализировать новый запуск, нужно положить
   туда соответствующие данные либо изменить путь `DATA` и путь поиска `ROOT`
   в первой ячейке.

Внутренний `/tokenize` доступен только у локального runner и может различаться
между версиями Ollama. Если токенизация или серверные `timings` недоступны,
скрипт сохраняет ошибку измерения и завершает эксперимент со статусом
`completed_with_errors`; такие результаты нужно проверить перед анализом.
